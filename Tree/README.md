## Introduction

A **Tree** is a non-linear, hierarchical data structure composed of nodes connected by directed edges. Unlike arrays, linked lists, stacks, and queues (which store data sequentially), trees represent relationships hierarchically:
- File systems (folders containing subfolders and files).
- The HTML Document Object Model (DOM).
- Abstract Syntax Trees (ASTs) generated by JavaScript compilers/parsers.
- Database indexing structures (B-Trees and B+ Trees).
- Decision trees and routing algorithms.

---

## Tree Terminology & Core Concepts

### Basic Definitions
- **Root:** The topmost node in the tree; the only node without a parent.
- **Node:** An element containing data and references/pointers to child nodes.
- **Edge:** The connection/link from a parent node to a child node.
- **Leaf (External Node):** A node that has no children (`node.left === null && node.right === null`).
- **Internal Node:** A node with at least one child.
- **Subtree:** A tree consisting of a node and all of its descendants.

### Height vs. Depth
- **Depth of a Node:** The number of edges from the tree's **root down to that node**. The root node is at depth $0$.
- **Height of a Node:** The number of edges on the **longest downward path from that node to a leaf**. A leaf node has height $0$.
- **Height of a Tree:** The height of the root node (i.e., maximum depth across all nodes).

### Degree of a Node
- **Degree of a Node:** The total number of children belonging to that node. In a Binary Tree, the maximum degree of any node is $2$.
- **Degree of a Tree:** The maximum degree among all nodes in the tree.

---

## Classifications of Binary Trees

### Full Binary Tree
Every node has either **$0$ or $2$ children**. No node has only $1$ child.

### Complete Binary Tree
All levels are completely filled except possibly the last level, and all nodes on the last level are as far **left as possible**. Complete binary trees are the foundation for array-backed **Binary Heaps**.

### Perfect Binary Tree
All internal nodes have exactly $2$ children, and all leaves are at the exact same depth. A perfect binary tree of height $h$ has exactly $2^{h+1} - 1$ total nodes.

### Balanced Binary Tree
For every node in the tree, the height difference between the left and right subtrees (the **Balance Factor**) is at most $1$:
$$|\text{Height}(\text{LeftSubtree}) - \text{Height}(\text{RightSubtree})| \le 1$$
Guarantees $O(\log n)$ height and fast operations.

### Degenerate (Skewed) Tree
Every parent node has only one associated child node. The tree essentially degenerates into a singly linked list, collapsing performance from $O(\log n)$ to $O(n)$.

## Binary Search Tree (BST) Fundamentals

### The BST Invariant Property
For every node $X$ in a Binary Search Tree:
1. Every node in the **left subtree** of $X$ must have a value **strictly less than** $X$'s value.
2. Every node in the **right subtree** of $X$ must have a value **strictly greater than** $X$'s value.
3. Both left and right subtrees must themselves be valid Binary Search Trees.

$$\text{All values in Left Subtree} < \text{Root Value} < \text{All values in Right Subtree}$$

### Time and Space Complexities

| Operation | Average Case (Balanced) | Worst Case (Degenerate / Skewed) | Space Complexity |
| :--- | :---: | :---: | :---: |
| **Search / Contains** | $O(\log n)$ | $O(n)$ | $O(1)$ iterative / $O(h)$ recursive |
| **Insert** | $O(\log n)$ | $O(n)$ | $O(1)$ iterative / $O(h)$ recursive |
| **Delete** | $O(\log n)$ | $O(n)$ | $O(1)$ iterative / $O(h)$ recursive |
| **Find Min / Max** | $O(\log n)$ | $O(n)$ | $O(1)$ |
| **Traversal (all nodes)** | $O(n)$ | $O(n)$ | $O(n)$ (Call stack or queue) |

## Tree Traversals

### Breadth-First Search (BFS / Level Order)
Visits nodes level-by-level from left to right using a **FIFO Queue**.

```javascript
levelOrder(root) {
  if (!root) return [];
  const result = [];
  const queue = [root];

  while (queue.length > 0) {
    const node = queue.shift();
    result.push(node.value);

    if (node.left) queue.push(node.left);
    if (node.right) queue.push(node.right);
  }
  return result;
}
```

### Depth-First Search (DFS: In-Order, Pre-Order, Post-Order)

#### 1. In-Order Traversal (`Left -> Root -> Right`)
> [!IMPORTANT]
> An in-order traversal of a valid Binary Search Tree **always visits keys in strictly ascending sorted order**!

```javascript
inOrder(node, result = []) {
  if (!node) return result;
  this.inOrder(node.left, result);
  result.push(node.value);
  this.inOrder(node.right, result);
  return result;
}
```

#### 2. Pre-Order Traversal (`Root -> Left -> Right`)
Used for cloning or serializing/deserializing tree structures.
```javascript
preOrder(node, result = []) {
  if (!node) return result;
  result.push(node.value);
  this.preOrder(node.left, result);
  this.preOrder(node.right, result);
  return result;
}
```

#### 3. Post-Order Traversal (`Left -> Right -> Root`)
Used for bottom-up operations, such as deleting a tree, computing folder sizes, or evaluating mathematical expression trees.
```javascript
postOrder(node, result = []) {
  if (!node) return result;
  this.postOrder(node.left, result);
  this.postOrder(node.right, result);
  result.push(node.value);
  return result;
}
```

## Core BST Operations & Step-by-Step Logic

### Insertion (Recursive & Iterative)
1. If the tree is empty, create the root node.
2. Otherwise, compare `value` against current node:
   - If `value < current.value`, navigate to `current.left`. If `current.left` is null, insert new node there; otherwise repeat.
   - If `value > current.value`, navigate to `current.right`. If `current.right` is null, insert new node there; otherwise repeat.

### Deletion (The Three Cases & In-Order Successor)

Deleting a node from a BST must preserve the BST invariant. There are three distinct scenarios:

```
Case 1: Node has NO children (Leaf Node)
Simply remove the node by setting its parent's pointer to null.

Case 2: Node has ONE child
Bypass the node by pointing the parent directly to the node's single child.

Case 3: Node has TWO children
1. Find the In-Order Successor (the smallest node in the right subtree).
   (Alternatively, the In-Order Predecessor: largest node in the left subtree).
2. Copy the successor's value into the target node.
3. Recursively delete the successor from the right subtree (the successor is guaranteed to have at most ONE child!).
```

```javascript
function deleteNode(root, key) {
  if (!root) return null;

  if (key < root.value) {
    root.left = deleteNode(root.left, key);
  } else if (key > root.value) {
    root.right = deleteNode(root.right, key);
  } else {
    // Found the target node to delete
    // Case 1 & 2: 0 or 1 child
    if (!root.left) return root.right;
    if (!root.right) return root.left;

    // Case 3: 2 children
    // Find min value in right subtree (In-Order Successor)
    let minNode = root.right;
    while (minNode.left) minNode = minNode.left;

    root.value = minNode.value; // Overwrite value
    root.right = deleteNode(root.right, minNode.value); // Delete duplicate successor
  }
  return root;
}
```

### BST Validation (Min/Max Boundary Check)

> [!CAUTION]
> Checking only `node.left.val < node.val && node.right.val > node.val` is a common interview bug! You must ensure **all** nodes in the left subtree are smaller than the ancestor root, and **all** nodes in the right subtree are greater.

```javascript
function isValidBST(root, min = -Infinity, max = Infinity) {
  if (!root) return true;

  if (root.value <= min || root.value >= max) {
    return false;
  }

  return (
    isValidBST(root.left, min, root.value) &&
    isValidBST(root.right, root.value, max)
  );
}
```

### Finding Closest Value to Target
Implemented in **[3-binarySearchTree.js](./3-binarySearchTree.js)**:

```javascript
function findClosestValue(root, target) {
  let closest = root.value;
  let current = root;

  while (current) {
    if (Math.abs(current.value - target) < Math.abs(closest - target)) {
      closest = current.value;
    }
    if (target < current.value) {
      current = current.left;
    } else if (target > current.value) {
      current = current.right;
    } else {
      break; // Exact match found
    }
  }

  return closest;
}
```

## Advanced Concepts: Self-Balancing Trees

### Why Balancing Matters
When sequential data (e.g. `[1, 2, 3, 4, 5]`) is inserted into a basic BST, the tree becomes completely skewed into a linear line of depth $n$. Operations degrade to $O(n)$. Self-balancing trees guarantee $O(\log n)$ worst-case bounds.

### AVL Trees (Balance Factor & 4 Rotations)
An **AVL Tree** is a strictly balanced BST where the balance factor $\text{BF} = \text{Height}(\text{left}) - \text{Height}(\text{right}) \in \{-1, 0, 1\}$.
When an insertion violates this balance ($|\text{BF}| > 1$), tree rotations restore balance in $O(1)$ time:
1. **Left-Left (LL) Case:** Right rotation.
2. **Right-Right (RR) Case:** Left rotation.
3. **Left-Right (LR) Case:** Left rotation on left child, then Right rotation on root.
4. **Right-Left (RL) Case:** Right rotation on right child, then Left rotation on root.

### Red-Black Trees
A self-balancing BST that colors each node either Red or Black and adheres to specific invariant rules (root is black, no two consecutive red nodes, every path from root to null has equal black nodes). Red-Black trees require fewer rotations during frequent insertions and deletions than AVL trees and form the underlying engine of C++ `std::map` and Java `TreeMap`.

## Common Interview Questions & Edge Cases

### Top Questions
1. **Validate Binary Search Tree:** Boundary checking with `(min, max)`.
2. **Lowest Common Ancestor (LCA) in BST:** Navigate using value comparisons in $O(\log n)$ time.
3. **Invert / Flip Binary Tree:** Swap left and right subtrees recursively.
4. **Kth Smallest Element in a BST:** In-order traversal counter.
5. **Construct BST from Preorder Traversal:** Rebuild using upper-bound constraints.
6. **Binary Tree Maximum Path Sum:** Post-order DFS calculating subtree gains.

### Edge Cases Checklist
- **Empty Tree (`root === null`):** Guard against accessing `root.val` or `root.left`.
- **Single Node Tree:** Height is $0$, diameter is $0$, closest value is the root itself.
- **Duplicate Values in BST:** Define whether duplicates are rejected, stored in left/right branches, or counted via a node frequency counter.
- **Skewed Trees:** Test deep unbalanced trees for call stack overflow risks in recursive implementations.
